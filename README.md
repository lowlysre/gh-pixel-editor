# gh-pixel-editor

Home of the **pixel sprite format**: a JSON format for pixel-art sprites that render cleanly in GitHub Actions logs and 256-colour terminals. The repo also hosts a browser editor for the format. Vanilla JS/HTML/CSS, no runtime dependencies.

- Spec: https://lowlysre.github.io/gh-pixel-editor/
- Editor: https://lowlysre.github.io/gh-pixel-editor/editor.html
- Schema: https://lowlysre.github.io/gh-pixel-editor/spec/sprite.schema.json

## Spec

[`site/spec/sprite-format.md`](site/spec/sprite-format.md) is the source of truth. The schema is [`site/spec/sprite.schema.json`](site/spec/sprite.schema.json); its `$id` is the published URL above, so keep the file path stable. Examples live in [`site/spec/examples/`](site/spec/examples/).

The site pages are generated from Markdown: the spec becomes `site/spec.html`, and the tutorial, how-to guides and explanation in `site/docs/` become the other pages. After editing any of them, run `npm run build-site`; `npm test` fails while a page is stale.

`site/js/validate.js` is a hand-written port of the schema (no validator dependency); a test guards its key constants against the schema.

The reference renderer for conformance is [`sprites.py`](https://github.com/lowlydba/quest-ops/blob/main/src/questops/sprites.py) in quest-ops.

## Editor

GitHub's log viewer paints a background over the whole line but a glyph over a shorter box, so two-colour half-block cells smear. The **Solid** preview shows a sprite under the CI constraint (one colour per text cell, `▀` with fg = bg); **Half** shows the terminal result; the smear preview models the log viewer.

Tools: pencil `P`, erase `E`, fill `F`, pick `I`, mirror-draw `M`, undo/redo `Ctrl+Z`/`Ctrl+Y`, help `?`. Import/export sprite JSON, export SVG, copy ANSI (256-colour escapes only). Work autosaves to the browser's local storage.

## Develop

```
npm run serve       # http://127.0.0.1:8080/ (serves ./site)
npm test            # node:test, no dependencies
npm run build-site  # regenerate the site pages from Markdown
npm run fixtures    # regenerate fixtures/ from the editor's renderer
npx pa11y-ci        # WCAG2AA check of every page in .pa11yci (needs npm run serve)
```

Pushes to `main` deploy `site/` to GitHub Pages via `.github/workflows/pages.yml`. Pull requests and pushes run the same accessibility check in CI through `.github/workflows/a11y.yml`.
## Conformance: parity unverified

`fixtures/` holds output for the `slime` example (base and every tier) per target: `solid`, `half`, `plain`, `svg`. They are generated by this editor (`npm run fixtures`), so they only catch regressions. They are **not** the Python renderer's output. Replace them with quest-ops reference output when available.

Choices the spec leaves open, all unverified against the reference renderer:

- `plain`: one glyph per pixel; `M` renders as a space; ramp levels map to `░░▒▒▓█` by `round(level*5/(n-1))`.
- `solid`: a tie within the same kind keeps the top pixel.
- `half`: a cell with only a bottom pixel uses `▄` (fg = bottom, no bg).
- ANSI run-merging and the `ESC[0m` placement.
- GitHub log line height and glyph aspect ratio are **unmeasured**; the preview geometry (cell width, line height, glyph/line ratio) is configurable and its defaults are guesses.
